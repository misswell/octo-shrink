默认 Retention.defaultDays = noRetain，下拉第一项就是「不保留」，老用户一律回落到该档 档位文案两条线不同 Tauri <option> 是「1 天 / 3 天」，Swift Retention.label() 是「保留 1 天 / 保留 3 天」，0 档两边都只写「不保留」 0 ≠ nil 禁止 if (days) / parseInt(v,10) || 3 / clamp(1,30) 启动 一个备份都不删，只读走「上次退出结没结清」的 clean-exit 记号（读一次即抹掉） 退出 是唯一的清理时机：按当前档位删过期记录与只被它们引用的备份；「不保留」把这次的记录和备份一起清掉 崩溃过的上一次 留下的备份再多留一次运行，等下一次正常退出收 —— 那可能是原图唯一的副本 恢复 备份已清时返回「原图备份已清理，无法恢复」，不假装成功
文案两条线逐字一致（app.js applyRetentionSetting() ↔ SettingsView.retentionCopyText）：0 档「本次运行的压缩记录和原图备份都会在关闭应用时清理；期间可以随时恢复原图。」其余档「过期的历史记录和原图备份将在关闭应用时自动清理。」
切换档位的 toast 也固定：原图备份改为不保留，关闭应用时清理记录和备份 / 原图备份保留 N 天，关闭应用时清理过期项。
崩溃 / 强杀不会走退出清理，那份备份可能是唯一还活着的原图 —— 所以清理只挂在正常退出，启动时一个备份都不删。永远不许写「下次启动时清理」（那是假承诺）、写「原图将在 3 天后删除」或「恢复原图仅限当前会话」。
